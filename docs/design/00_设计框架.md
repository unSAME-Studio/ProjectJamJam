## 1. 一句话

**按住吸，松开吐。吸进去什么，就涌现出什么；吸够一样东西，它就在你肚子里变成更高级的东西。**
从一个灰色小人吐出游戏 Logo 开始，一路吸、吐、坍缩到宇宙，最后吐出「涌现」这两个字本身。

## 2. 支柱

| # | 支柱 | 检验问题 |
|---|---|---|
| 1 | **好奇**：这个东西会涌现出什么？ | 玩家看到一个新东西，是不是想马上吸它 / 撞它？ |
| 2 | **一个动词**：吐纳，从头到尾不变 | 新加的东西是不是只用"按住 / 松开"就能玩？ |
| 3 | **增殖不是破坏**：世界越来越多，但每次减少也是一次涌现 | 这次减法有没有带字幕？是不是本身也好笑？ |
| 4 | **认真地荒唐**：千禧年中文互联网的一本正经 | 文案有没有在解释笑点？ |

North Star 不变：**它是否让玩家更想知道"接下来还能涌现出什么"？**

## 4. 系统总览

```
            ┌──────────── 玩家：吐纳 ────────────┐
            │  吸：拉近 → 进丹田                   │
            │  吐：喷出全部内容物 + 基础气流        │
            └───────┬──────────────────┬──────────┘
                    │ 吸走（回收）       │ 喷出（冲量）
                    ↓                  ↓
   丹田 ── 同类够数 → 肚子里坍缩      物体被高速撞中 → 涌现（emits）
     │                                 │       └→ 碰撞配方（A 撞 B → C）
     └ 满级 → 幕结束                   ↓
                                 新物体继续飞、继续撞 → 连锁
                                       │
              NPC 被吸过或被撞中 → 开窍 → 自己做小吐纳
                                       │
                           世界：同类堆积 → 自然坍缩（门槛 ×1.5）
                                 消化者吃东西 → 涌现别的
                                 太远太久 → 归档进回收站
                                 逼近上限 → 蓝屏
```

所有事件都汇到 `EmergenceStats`（事件账本），`ActDirector` 根据账本推进幕。

## 5. 消化：每一次减少本身也是一次涌现

不能偷偷删东西。所有减法都要有字幕或演出。

| 阀门 | 触发 | 效果 |
|---|---|---|
| **玩家吸**（新的主阀门） | 按住 | 东西进丹田，世界里少了；同类够数在肚子里坍缩 |
| 自然坍缩 | 同类 ≥ N×1.5 聚在一起 | 合成一个 +1 层的东西 |
| 开窍 NPC 吸 | 自动 | 小范围回收 |
| 消化者 | 下水道吃水、垃圾车吃垃圾山、回收站吃一切 | 吃够了涌现别的 |
| 归档 | 太远 / 落地 5 秒不动的小东西 | 飞进屏幕角回收站 +1 |
| 尺度跃迁 | 幕切换 | 上一幕烘焙成静态地表 |
| 蓝屏（兜底） | 逼近物理上限 | 进入桌面插曲 |

字幕本身也要节流，见 03 §2.5。

## 6. 内容语法

### 6.1 一行 = 一个东西

见 `content/README.md`。关键列：`emits`（被撞喷什么）、`collapse_n / collapse_into`（一堆它叫什么）、`eats`（吃什么）、`recipes`（被什么撞变什么）、`size / anchored`（能不能被吸）。

### 6.2 五种涌现语法

| 语法 | 问题 | 例 |
|---|---|---|
| container | 这里面有什么？ | ATM → 钱 |
| reproduce | 它会生出更多自己吗？ | 鸽子 → 鸽子、新建文件夹 → 新建文件夹 (2) |
| concept | 它象征什么？ | 钱 ×20 → 资本 |
| system | 它会变成一种游戏机制吗？ | 系统碎片 → 游戏性 |
| recursive | 结果会生回来源吗？ | 苹果 → 树 → 苹果；GAME JAM → 游戏 → GAME JAM |

### 6.3 规则

- 产出同层或 +1 层；坍缩永远 +1 层
- 每个物体回答两个问题：**里面有什么**、**一堆它叫什么**
- 每一幕 approved 8–12 个；先进表，再进引擎；不到 `approved` 不做资产
- 不给单个物体写专属脚本，只用通用行为（04 方向 2 的地基）

## 7. 技术备忘（Godot 4）

- 物理硬上限 ~300 `RigidBody3D`
- 坍缩检测：丹田内是计数，立即判断；世界内按 id 分桶，每 0.25s 空间查询一次
- 幕切换后旧物体转 `MultiMesh`，退出物理
- `PlayerBody` 接口：`hold_begin() / hold_tick(dt) / release()`；小人、指针、挖掘机、地球各实现一份，吸 / 吐的通用逻辑在 `Dantian`（丹田）组件里
- `EmergenceStats` 单例记录所有事件；`ActDirector` 用数据配置的结束条件监听它
- CSV → `.tres` 一键导入；`tools/validate_table.py` 校验引用
- 美术：低多边形 + 纯色，AI 生成模型后统一风格；没模型的东西用彩虹 `TextMesh` 名字兜底
