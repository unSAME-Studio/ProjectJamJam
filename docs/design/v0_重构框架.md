# 《涌现出来了！》设计重构 v0（讨论稿）

> 状态：讨论稿。标【待确认】的地方需要拍板。
> 原 brief 保留为素材库，本文只重建骨架：**核心交互 → 消化机制 → Meta 节奏 → 内容语法**。

---

## 0. 对原 brief 的拆解

原 brief 的笑点（把"涌现"字面化）成立，但作为游戏有三个结构性问题：

| 问题 | 表现 | 本稿的处理 |
|---|---|---|
| 只有"增"没有"减" | 物体数量单调上升 → 性能爆炸 + 信息过载 + 后期全是噪音 | 让"减"本身就是涌现（§2） |
| 玩家决策太薄 | 按空格喷水 → 看 → 再喷，玩家只是个开关 | 加入"方向 + 蓄力 + 碰撞配方"，并让能力本身传染（§1） |
| Meta 是一张清单 | QUEST/COMBAT/GAME JAM 各自出现，没有节奏 | 用"尺度"把它们串成三幕 + 插曲（§3） |

**关键反转**：涌现的真实定义是"大量微观个体 → 一个宏观整体"。
原 brief 只做了"一个东西 → 很多东西"（这其实是*分裂*，不是涌现）。
本稿把另一半补上：**很多东西 → 坍缩成一个更高级的东西**。
这一半同时解决了垃圾回收、视角升级和 punchline。

## 1. 核心交互

### 1.1 唯一动词：涌现

- **按住**：扎马步蓄力，镜头推近，"力量——"
- **松开**：从丹田喷出冲击，"涌现出来了！！！"
- **方向**：朝镜头/摇杆方向喷
- **蓄力档位**【待确认，可砍】：
  - 短按 = 字面涌现（ATM → 钱）
  - 满蓄 = 多疯一步（ATM → 资本）
  - 同一物体两种结果，给"猜测"一个杠杆；内容量翻倍，jam 内可只给部分物体做满蓄版本

### 1.2 连锁的物理规则（让涌现真的自己发生）

1. 被玩家冲击打中 → 触发该物体的涌现
2. 任何物体**以足够速度撞上**另一个可涌现物体 → 也触发（喷出来的东西就是下一发子弹）
3. **碰撞配方**：特定 A 撞 B → 特殊结果（钱 撞 人 → 公司）。没配方时回落到 B 自己的涌现
   - 这是"如果我把这个和那个放一起会怎样"真正发生的地方
   - 配方要稀疏、可猜，类似 Little Alchemy

### 1.3 能力传染：从角色到上帝的桥

被冲击打中的 NPC 爬起来，沉默一秒，"原来如此。"，然后**也学会了涌现**，开始自主喷射。

- 玩家的能力本身在世界里涌现、扩散
- 当足够多 NPC 在自己喷的时候，玩家不再特殊 → 镜头离开玩家顺理成章
- 这条机制同时是：连锁反应的引擎 / 视角转移的叙事理由 / 一个不用解释的"涌现"示范

### 1.4 镜头方案

推荐：**跟随角色起步，镜头随世界规模"呼吸"，最终被迫变成上帝视角。**

- 镜头距离 = f(活跃物体数量 / 场面范围)，连锁越大镜头越远（自动，不需要玩家操作）
- 蓄力时短暂推近（喜剧节奏），释放后回弹
- 拉远到阈值 → 触发**尺度跃迁**（§3），玩家的"身体"换成上一尺度涌现出的最大的东西

| 尺度 | 玩家是谁 | 镜头 | 喷的是什么 |
|---|---|---|---|
| I 街道 | 一个小人 | 第三人称跟随 | 水 / 气 |
| II 城市 | 一栋大楼 / 一家公司（坍缩出来的） | 俯视等距 | 人流 / 车流 / 钱 |
| III 星球→宇宙 | 地球 | 太空 | 文明 / 卫星 / 概念 |

动词永远不变（蓄力 → 涌现出来了），只有尺度在变。类似块魂的尺度成长 + Powers of Ten。

【待确认】是否接受"玩家身体会换"；保守方案是始终是那个小人，只是越来越小地站在大东西上面。

## 2. 消化机制（反涌现 / 垃圾回收）

原则：**每个减法都必须本身也是一个涌现事件**，不能是偷偷 despawn。

### 2.1 坍缩（主阀门）

同类物体在一定范围内聚集 ≥ N 个 → 合并成一个更高级的物体，带大字：

- 30 只鸽子 → **鸽群** → 鸽群再聚 → **鸽子工会**
- 很多钱 → **资本**
- 很多上班族 → **公司**
- 很多公司 → **经济**
- 很多游戏 → **GAME JAM**

效果：物体数量骤降、尺度上升、喜剧节拍、推进进度——一个机制干四件事。
坍缩是**进度的唯一来源**，不需要任务。

### 2.2 消化者（局部阀门）

部分物体吃掉其他东西，然后自己涌现别的：

- 下水道 吃水 → 涌现鳄鱼
- 垃圾车 吃垃圾 → 涌现回收站
- 税务局 吃钱 → 涌现表格
- 后期 黑洞 吃一切 → 涌现"信息悖论"

### 2.3 归档（UI 阀门）

离镜头太远 / 太久没动的小东西，飞进屏幕角落的**图鉴**，图鉴 +1。

- 图鉴本身是一个涌现出来的 UI（见 §3.2）
- 给收集欲一个出口，同时回收物体

### 2.4 尺度跃迁（硬阀门）

镜头拉远到阈值 → 低一级尺度的所有物体烘焙成静态贴图 / MultiMesh 噪点，成为新尺度的地表纹理。
上一幕的全部混乱变成下一幕的一块"地砖"。

### 2.5 假崩溃（兜底阀门，同时是 meta 笑点）

如果物体数量还是逼近硬上限：

> **BUG 涌现出来了**

假蓝屏 / 假报错弹窗 → "重新启动" → 直接进入下一尺度。
性能兜底 = 一个笑点。

## 3. Meta 节奏：三幕 + 插曲

Meta 层只做 **UI 碎片 + 几个大插曲**，不做系统。

### 3.1 结构

```
[冷开场] 没有 UI、没有标题，一个灰色小人站在街上
   ↓ 第一次涌现
[插曲 A] 「游戏涌现出来了」
   ↓
[第一幕 · 街道]  个体 → 物体 → 生物
   ↓ 坍缩积累 / 镜头拉远
[插曲 B] 「系统涌现出来了」（feature creep 连发）
   ↓
[第二幕 · 城市]  NPC 传染 → 机构 → 经济
   ↓ 镜头继续拉远
[插曲 C] 「GAME JAM 涌现出来了」
   ↓
[第三幕 · 现实]  星球 → 文明 → 宇宙
   ↓ 一切坍缩成一个东西
[终幕] 「涌现涌现出来了！」
```

### 3.2 各插曲

**插曲 A · 游戏涌现出来了**（开场 ~30 秒）
- 游戏启动时什么都没有。玩家第一次涌现 → 标题 Logo 被喷出来，带物理掉在街上，可以被推着走
- 之后 UI 一块一块涌现：分数、小地图、图鉴、设置按钮……每个都是从某个物体里喷出来的实体，飞到屏幕位置"贴上去"
- 告诉玩家这个游戏的规则：**连这个游戏也是涌现出来的**

**插曲 B · 系统涌现出来了**（第一幕→第二幕）
- 快速连发、每个只活几秒的半成品系统：QUEST / COMBAT（NPC 头上冒血条然后没用）/ LEVEL UP / CRAFTING 弹窗 / SOULSLIKE
- 这些系统彼此坍缩 → **"游戏性"**这个物体 → 掉进城市
- 拿 feature creep 开玩笑，同时完成尺度过渡

**插曲 C · GAME JAM 涌现出来了**（第二幕→第三幕）
- 镜头继续拉远：整座城市原来是一台显示器里的画面，显示器在一张 jam 桌上
- 桌边一群开发者，屏幕上写着 `Theme: EMERGENCE`
- 他们在做的就是这个游戏。再拉远——jam 会场在一个星球上 → 进入第三幕

**终幕 · 涌现涌现出来了！**
- 第三幕所有东西最终坍缩成一个巨大的实体文字：**「涌现」**
- 玩家对它涌现 → 它喷出的是……jam 主题公告、开发者名字（制作人员名单作为物理物件喷出来）
- 名单砸中一个灰色小人 → 回到冷开场。递归闭合

### 3.3 Meta 的分寸

- 主体时间都在玩物理连锁，meta 只占节拍点
- 所有 meta 文本保持 deadpan：系统字幕永远是平静的通报体，「XX 涌现出来了。」

## 4. 内容语法（让内容可控）

### 4.1 每个物体的数据

```
EmergenceDef (Godot Resource)
  id / 显示名 / tier(尺度层级 1-6)
  on_hit:      喷什么、多少、力度、台词、是否替换自身
  on_charged:  (可选) 满蓄版本
  collapse:    聚集多少个 → 坍缩成什么
  eats:        (可选) 吃什么 → 吃够后涌现什么
  recipes:     (可选) 被什么撞 → 特殊结果
```

### 4.2 规则

- 产出只能是**同层或 +1 层**；坍缩永远是 **+1 层**。保证尺度单调上升，不会乱
- 每一幕约 8–10 种物体，总计约 25–30 种
- 每个物体回答两个问题：**"里面有什么"**（字面）和**"一堆它叫什么"**（坍缩）。第二个问题就是新增的笑点来源

### 4.3 示例链

```
ATM ─喷→ 钱 ─×20 坍缩→ 资本
钱 撞 路人 ─配方→ 小公司 ─喷→ 上班族 ─×10 坍缩→ 公司
公司 ─喷→ 电脑 ─喷→ 游戏 ─×5 坍缩→ GAME JAM（插曲 C 的触发）
```

## 5. 还需要一起确认的事

1. **jam 时长 / 人数 / 目标时长**：决定是三幕还是一幕半
2. **2D 还是 3D**：3D 等距正交镜头（toy diorama）vs 2D 俯视。2D 成本低一个数量级，拉远镜头天然好做；3D 更有 Goat Sim 味。仓库是 Godot，两者都行
3. **蓄力双档**要不要（内容 ×1.5–2）
4. **玩家身体随尺度更换** vs 始终是小人
5. **有没有结局**：推荐有（终幕递归），jam 评审需要一个完整弧线
6. **语言**：「涌现出来了」的气功语感是中文特有的；英文"has emerged"弱很多。主语言中文 + 英文字幕？配音谁来喊？
7. **失败状态**：推荐没有。唯一"失败"是假崩溃，而它也是推进
8. **图鉴**：做不做；做的话是唯一的长期收集目标

## 6. 技术备忘（Godot）

- 物理物体硬上限（例如 300 个 RigidBody），超出走坍缩 / 归档 / 假崩溃
- 坍缩检测：按类型分桶 + 低频（每 0.25s）空间查询，不要每帧
- 尺度跃迁后，旧物体烘焙为 MultiMesh，不再参与物理
- `EmergenceDef` 用 `.tres` 资源，设计师在编辑器里直接拖产出物，零代码加内容
